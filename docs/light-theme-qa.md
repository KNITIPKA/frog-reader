# Light palette review and correction

Date: 2026-09-21. Scope: app chrome, neutral surfaces, actions, selection, and reader controls.

## Evidence and diagnosis

The user supplied seven original device screenshots, then four screenshots of
the first implementation (Reading, reader controls, Book info, Backup). Those
four later images are the authoritative feedback for this correction.

The first revision made surfaces more consistent but combined a yellow-white
canvas (`#F5F4EF`) with olive-grey controls (`#E9EBE2`, `#E6EBDF`). Against white
cards that cast looked dirty. In the reader, two closely related filled layers
also made nested buttons look disabled. The contrast tests passed that revision;
text contrast alone did not establish that its visual character was appropriate.

## Screen review

1. **Reading settings — corrected.** The canvas is now a clean neutral grey;
   segmented groups and icon tiles have no yellow/olive cast. Active segments
   and switches retain a clearly contrasting forest green. Checked in the native
   `LightReadingSettingsPreview`.
2. **Reader controls — corrected.** The sheet stays white. Inset groups are
   neutral and stepper buttons have separate white faces; selected options use
   the accent and its matching foreground. Unselected animation icon tiles use
   the same neutral control role. Checked in `LightReaderControlsPreview`.
3. **Book information — corrected.** A neutral canvas separates the white
   identity/publication/technical cards without the previous cream cast.
   Checked in `LightBookInfoPreview` with in-memory sample metadata.
4. **Backup — corrected.** The overview card is white with a solid primary CTA
   and neutral restore button. The selected backup scope uses a fresh mint fill;
   unselected controls and the Change button use clean neutrals. Checked using
   the actual backup components in `LightBackupControlsPreview`, including the
   disabled schedule when no folder is selected.
5. **Library — consistent with the corrected roles.** The header is a restrained
   mint gradient, content and navigation stay white, and expanded import options
   use neutral surfaces. Native grid, Midnight, expanded-menu, and large-text
   previews were rendered and inspected; sample covers are generated by the
   app's existing fallback renderer.
6. **Profile — shared palette applies.** The neutral canvas, icon tiles and dock
   share the same roles; the identity gradient uses forest green. Profile native
   previews were inspected during the first revision. A separate final profile
   capture after the neutral-hue correction was not made.

## Verification

- JBR `./gradlew test :app:assembleDebug` succeeded after the corrected production
  palette and controls: 948 tests, 0 failures, 0 errors, 5 skipped.
- A subsequent `:app:assembleDebug` succeeded after splitting debug previews into
  two files. No production behavior changed in that split.
- `git diff --check` passed.
- Contrast tests cover normal and secondary text, action/error pairs, fixed
  accents, header/profile alpha composition, selected navigation, nested reader
  controls, and overlapping quote/selection highlights. Minimums are 4.5:1 for
  tested text pairs and 3:1 for tested control outlines/progress fills.
- New regression checks reject yellow/olive casts in fixed Light neutrals and
  require visible luminance separation between stepper buttons and their group.
- Android Studio showed **Up-to-date** for the reviewed native previews. Screenshots
  were inspected inline through Computer Use; standalone image files were not
  exported. Some preview captures include IDE layout-bound overlays; those are
  diagnostic outlines, not application borders.

These are static native preview and build checks. This run did not install the
final APK, operate a physical device, test TalkBack, or validate arbitrary
wallpaper-derived palettes on Android. Backup preview data is in-memory and does
not access or change the user's backups. Publisher colors, cover art, image export
backgrounds, and the system-themed Glance widget are intentionally independent
of the fixed Light chrome palette.

The maintained color contract is [light-theme.md](light-theme.md), also referenced
from the repository's `AGENTS.md`.
